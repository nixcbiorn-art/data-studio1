# Источники API

Каждый `*.json` в этой папке описывает один или несколько эндпоинтов.
Формат и все поля — в README проекта, раздел «Подключение нового API».

## Что здесь лежит

**`redcat_estate.json`** — основной набор, включён:

| ключ | эндпоинт |
|---|---|
| `regulations` | `/api/v1/estate/regulations` |
| `tariffs` | `/api/v1/estate/regulation_tariff_cards` |
| `housing_complexes` | `/api/v2/estate/housing_complexes` |
| `apartments` | `/api/v2/estate/housing_complexes/listing_apartments` |

**`redcat_hc_by_object_type.json`** — те же ЖК, но с фильтром
`filter[object_type_id]` = 3 / 5 / 7 / 8. **Выключены** (`"enabled": false`).

### Зачем нужны варианты по типу объекта

Обычно не нужны: `housing_complexes` без фильтра по типу возвращает все
типы сразу, и четыре дополнительных обхода — это четырёхкратная лишняя
нагрузка на API ради тех же данных.

Включать их стоит в двух случаях:

1. **Обход лимита пагинации.** Если ЖК в регионе больше, чем API отдаёт за
   один запрос (обычно ~10 000), общий список обрывается. Разбивка по типам
   делает каждый запрос меньше потолка. Понять, что это ваш случай:
   ```
   python redcat_scraper.py --diagnose housing_complexes
   ```
   Проверка прямо скажет, сколько записей заявляет API и упрётся ли обход
   в лимит.

2. **Нужны отдельные срезы по типам** для сравнения между собой.

### Как включить

Поменяйте `"enabled": false` на `true` у нужных вариантов. Если включаете
их вместо общего списка, выключите `housing_complexes` в
`redcat_estate.json` — иначе те же ЖК соберутся дважды и попадут в
дубликаты.

⚠️ Значения `object_type_id` (3, 5, 7, 8) взяты из вашего запроса и здесь
не проверены — рабочего токена у меня нет. Перед использованием убедитесь,
что они соответствуют нужным типам и что их набор покрывает все ЖК: сумма
по четырём типам должна сойтись с общим числом из
`--diagnose housing_complexes`. Если не сходится — существуют другие
значения `object_type_id`, и часть ЖК потеряется.
